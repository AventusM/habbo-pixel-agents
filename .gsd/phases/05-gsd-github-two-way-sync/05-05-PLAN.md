# S05: GitHub→GSD webhook branch

**Milestone:** M005
**Slice:** S05

**Goal:** Extend the existing HMAC-validated POST /webhooks/github receiver (scripts/web-server.mjs) with a GSD-sync branch: on issues.closed/reopened, parse the M00X/S0X title prefix and record evidence/flag the linked slice — with loop guards (transitions only, bot-marker ignored, one hop max).
**Demo:** Close a scratch M00X/S0X-titled issue on GitHub; GSD records validation evidence (or flags the slice) within the webhook debounce window.

## Must-Haves

- 1) Closing/reopening a M00X(/S0X)-titled issue appends exactly one sync intent to .gsd/runtime/github-sync/inbox.jsonl and one GSD notification row (webhook redelivery does not duplicate). 2) Loop guards covered by tests: non-transition actions, bot senders, and gsd-sync body markers are ignored. 3) Webhook contract unchanged: board debounce behavior untouched; sync failures can never break the 202 response. 4) npx vitest run + npx tsc --noEmit + lint green.

## Proof Level

- This slice proves: runtime + tests

## Integration Closure

Sync branch runs inside handleGithubWebhook on the same verified payload path as the board debounce; outputs are file-based (.gsd/runtime/github-sync/ + .gsd/notifications.jsonl) so no new runtime dependency or server API surface; exactly-once enforced by a dedupe state map keyed on issue+action+transition timestamp.

## Verification
