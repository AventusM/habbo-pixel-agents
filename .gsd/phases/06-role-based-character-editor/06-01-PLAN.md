# S01: Role outfits render at spawn

**Milestone:** M006
**Slice:** S01

**Goal:** Wire the existing ROLE_OUTFIT_PRESETS + getRolePreset into the spawn path so spec.outfit is assigned by role, and evaluate external reuse candidates for the editor before building.
**Demo:** Spawn one agent per role (Atlas, Sisyphus, core-dev, planning): each renders a visually distinct Nitro outfit instead of the hardcoded fallback.

## Must-Haves

- All agent roles spawn with distinct, role-resolved outfits (spec.outfit set from ROLE_OUTFIT_PRESETS/getRolePreset per the code's TeamSection role model; every classified agent gets its role outfit and unclassified agents get a deterministic distinct preset) instead of the renderer's hardcoded variant palette; role-granularity reconciliation (vision's 8 named roles vs the code's 4 TeamSection roles) recorded as a decision; no behavior change for PixelLab-backend agents; reuse evaluation (internal presets vs external candidates) recorded as a decision; vitest + tsc clean.

## Proof Level

- This slice proves: unit + visual (screenshot of all roles side by side)

## Integration Closure

Bridge agents (hooks-feed), debug spawn, and demo agents all resolve outfits through the same lookup; PixelLab path explicitly untouched with a code comment.
