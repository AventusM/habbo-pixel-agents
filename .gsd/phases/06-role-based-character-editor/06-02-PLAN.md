# S02: Character editor UI with live preview

**Milestone:** M006
**Slice:** S02

**Goal:** Build an in-room character editor UI with a live WYSIWYG Nitro preview: select one of the four TeamSection roles, customize that role's outfit (shirt color plus hair style/color, catalog-driven), and watch the preview avatar update immediately; switching roles shows each role's own draft outfit. Per D032 the editor is built in-repo on ROLE_OUTFIT_PRESETS + FIGURE_CATALOG with no external Habbo editor; persistence and restyle-of-live-agents are explicitly S03, not here.
**Demo:** Open the editor, pick the Atlas role, change shirt color and hair, watch the preview avatar update live; switching roles shows each role's current outfit.

## Must-Haves

- An editor panel is reachable from the room shell; its role selector lists the four TeamSection roles (planning, core-dev, infrastructure, support) and, on switch, shows each role's own current draft outfit with no cross-role bleed.
- Changing shirt color and hair (style via FIGURE_CATALOG hair items and hair color via HAIR_PALETTE) re-renders the preview avatar immediately through the same Nitro path in-room avatars use (createNitroAvatarRenderable + outfitToFigureParts + shared SpriteCache), with no new WS message types.
- Draft outfit state lives in a src/state store and is bound to React through a custom hook (D021); the editor components are presentational (props in, JSX out, no store/client imports, no app logic).
- Drafts are independent clones: editing one role never mutates ROLE_OUTFIT_PRESETS, DEFAULT_PRESETS, or another role's draft.
- npx vitest run + npx tsc --noEmit + npm run lint are green and node esbuild.config.mjs succeeds.

## Proof Level

- This slice proves: unit + visual (live preview screenshot). The unit/structural tests plus the pure createNitroAvatarRenderable consumption test are the executable proof; the side-by-side/live preview screenshot is recorded NEEDS-HUMAN when the extension host cannot be launched in the headless continuation environment (same convention as S01).

## Integration Closure

The editor draft resolves through the exact OutfitConfig layer the spawn path uses (ROLE_OUTFIT_PRESETS / getRolePreset -> outfitToFigureParts), and the preview consumes createNitroAvatarRenderable with the shared (window).spriteCache, so what the editor shows is what spawn renders. No new WS message types; the PixelLab backend stays untouched (it ignores spec.outfit by design, S01/T03). Persistence across reload and restyling live agents are deferred to S03.

## Verification

- Draft mutations and role switches emit a debug-level console log only; the editor state is observable through outfitStore.get()/subscribeSelector (no new WS message types, no new host events).
